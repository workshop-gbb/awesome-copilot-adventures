# Composition patterns (v4.0.0)

Patterns are ways to organize one conclusion on the 1280 x 720 stage. They are not fixed slide
templates and they are not tied to one reference deck. Choose the pattern after choosing the
narrative role, visual question, family, and archetype.

## Composition principles

1. **One conclusion.** The title states what the audience should conclude.
2. **One dominant region.** The eye knows where to start within one second.
3. **Evidence near the claim.** Source, number, label, and visual stay together.
4. **Hierarchy before decoration.** Scale, position, contrast, and whitespace do the work.
5. **A support module is allowed.** It must strengthen the same conclusion, not start a second story.
6. **No generic card reflex.** Cards are one option among diagrams, charts, media, simulations,
   tables, processes, interactions, and editorial compositions.

## Macro layouts

### 1. Editorial stage

Use for a thesis, reframe, tension, or memorable line.

- large statement or quote
- one supporting sentence
- optional evidence row or source
- generous negative space

Good archetypes: hero statement, quote, big number, before/after ruler.

### 2. Hero plus evidence

Use when one claim needs two or three proofs.

- dominant claim in the upper or left region
- evidence numbers, mini charts, or source cards below or right
- one accent color for the claim; evidence uses semantic colors

Good archetypes: hero statement + big numbers, quote + KPIs, recommendation + risk row.

### 3. Split comparison

Use for before/after, option A/B, current/target, or two operating models.

- two balanced columns
- shared comparison axis
- explicit difference or verdict
- no repeated prose that forces the audience to compare paragraphs

Good archetypes: compare, dodont, ruler, two diagrams, two code states.

### 4. Visual plus insight rail

Use when a chart, diagram, or simulation needs interpretation.

- 65 to 75 percent for the visual
- 25 to 35 percent for two or three insights
- the rail explains why the visual matters, not what each label already says

Good archetypes: chart + KPI rail, simulation + guardrails, diagram + decisions.

### 5. Full-width analytical stage

Use for a chart, timeline, gantt, architecture, or detailed table that needs width.

- title and source above or below
- one full-width visual
- legend inside the visual boundary
- optional watch line at the bottom

Good archetypes: line, waterfall, heatmap, sequence, request path, gantt.

### 6. Small multiples

Use to compare several entities with the same measure or state.

- identical scales and frames
- two to four panels
- one highlighted panel
- shared legend and unit

Good archetypes: repeated mini charts, scenarios, persona outcomes, regional scorecards.

Do not use this for unrelated ideas. Unrelated cards are a list, not small multiples.

### 7. Matrix or structured field

Use for two dimensions, trade-offs, decision criteria, or categorical lookup.

- strong row/column hierarchy
- highlighted recommendation or exception
- short cell content
- explanatory note outside the matrix

Good archetypes: table, quadrant, heatmap, tiers, glossary, decision matrix.

### 8. Layered or zoned diagram

Use for architecture, boundaries, ownership, or deployment.

- zones establish context
- nodes carry official icons
- connectors show direction and protocol
- legend explains line and color meaning
- prose moves to notes

Good archetypes: C4, deployment, architecture, network, data pipeline.

### 9. Process path

Use for order, state, lifecycle, or work over time.

- one reading direction
- numbered or dated transitions
- exception paths visually distinct
- final state or decision visible

Good archetypes: steps, timeline, state machine, sequence, flowchart, swimlane.

### 10. Product or system simulation

Use when real behavior is stronger evidence than a description.

- faithful light-theme surface; terminal may be dark
- realistic content and labels
- focused state, not a screenshot dump
- insight rail or speaker notes explain the mechanism

Good archetypes: terminal, VS Code, GitHub Copilot Chat, Azure portal, GitHub PR, browser, phone.

### 11. Interactive control panel

Use when the audience should answer, choose, calculate, inspect, or test a scenario.

- controls first
- output updates on the first action
- result explains why
- neutral initial state
- complete static state under reduced motion

Good archetypes: quiz, assessment, calculator, chainsim, toggle, hotspots, poll.

### 12. Immersive media

Use when the image, illustration, or video is evidence.

- media occupies the stage
- caption and source remain legible
- one annotation layer at most
- no decorative stock image behind paragraphs

Good archetypes: figure, video, custom SVG illustration, annotated screenshot.

### 13. Technical artifact

Use when implementation detail is the evidence.

- one artifact at readable scale
- highlight only the relevant lines or branch
- explain consequence, not syntax
- link to the full source

Good archetypes: code window, diff, JSON tree, markdown runbook.

### 14. Decision and recap

Use to converge after analysis.

- recommendation or decision at the top
- evidence, risks, owner, and timing below
- visual closure, not a summary of every previous slide

Good archetypes: recommendation ledger, decision matrix, 30/60/90 timeline, checklist.

## Content-to-form map

| Content shape | Preferred forms |
|---|---|
| one memorable idea | hero statement, quote, media reveal |
| magnitude | big numbers, horizontal bar, KPI |
| change over time | line, area, ruler, waterfall |
| share of whole | donut, stacked 100, treemap |
| categorical comparison | columns, table, small multiples |
| target or threshold | gauge, progress bars |
| dates and milestones | timeline |
| work over time | gantt |
| options and trade-offs | tiers, quadrant, compare, matrix |
| facts plus consequences | ledger |
| fixed order | steps, flowchart |
| actors exchanging messages | sequence |
| changing states | state machine |
| ownership across teams | swimlane |
| system boundaries | C4, zoned architecture |
| data movement | data pipeline, event-driven diagram |
| product behavior | simulation |
| scenario exploration | interactive |
| implementation change | code, diff, tree |
| visual evidence | figure, video, annotated SVG |

## Cadence rules

- A divider resets the visual rhythm. The next one or two slides include a hero.
- Do not repeat the same exact archetype three times in a row.
- Do not keep the same macro layout for an entire section, even when the component changes.
- Alternate dense and breathable slides where the story allows.
- A chart sequence changes the analytical question, not only the chart color.
- A diagram sequence changes the relationship being explained: context, flow, state, deployment,
  ownership, or dependency.
- Workshops alternate explain, show, try, compare, and debrief.
- Keynotes alternate tension, proof, reveal, and reflection.

## Diagramation checks

- Keep a clear top-to-bottom or left-to-right reading path.
- Align major regions to a shared grid.
- Use at most three primary columns; four is reserved for small multiples or compact cards.
- Keep labels close to the object they name.
- Let the primary visual touch the lower composition zone; avoid a small block floating in the
  middle of the slide.
- Use whitespace to separate roles, not arbitrary boxes.
- A decorative shape must reinforce grouping, direction, hierarchy, or meaning.
- If removing a shape does not reduce comprehension, remove it.

## Selecting a pattern

Before building, answer:

1. What is the one conclusion?
2. What evidence makes it credible?
3. What visual question is being answered?
4. Which family and archetype answer that question best?
5. Which macro layout gives that archetype enough stage?
6. What did the previous two slides look like?
7. Is the next slide changing narrative role as well as visual form?
